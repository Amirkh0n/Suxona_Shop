2. Critical Architectural Findings (schema vs docs conflicts)
These are the issues to settle before writing code:

A. The cart is server-side, not a local Zustand store. 05-state-management.md says the cart is a Zustand store persisted to localStorage. But the schema has full server cart endpoints (/cart, /cart/items), already grouped by store, and 01-overview says guests cannot add to cart (auth required). Since the schema is authoritative, the cart must be server state managed by TanStack Query, not Zustand. Zustand's role for cart should shrink to optional optimistic UI / a pre-login "pending add" buffer. This is the single biggest deviation from the docs and I want your decision on it.

B. Registration cannot complete in the browser alone. register returns a Telegram deep link, and account activation happens through telegram/verify, which is called by the Telegram bot, not the frontend. So the "phone + password" browser signup ends at a "open Telegram to verify" screen. There is no pure-web activation path in the current API.

C. Telegram Mini App auto-login has no endpoint yet. telegram/verify is bot-to-backend only. There is no initData → JWT exchange endpoint. So Mini App auto-login is genuinely future-phase. We architect an abstraction layer for it, but it stays stubbed.

D. "Become a seller" is an application + admin approval, not instant. 01-overview says a user becomes a seller by creating a store. The schema says you submit a store-application that an admin approves/rejects. The seller flow must model pending / approved / rejected states.

E. Order statuses must come from the schema enum, not the doc list. The UI doc lists New/Confirmed/Preparing/On-the-way/Delivered/Cancelled, but the transition endpoints are accept/reject/delivering/complete/cancel. The status enum in OrderDetail is the truth and I'll align the UI labels to it.

F. No favorites API. Product cards spec a favorite button, but there's no endpoint. It stays visually present but non-functional (or hidden) for MVP.

3. Proposed Architecture
Stack (locked by docs): React + TS + Vite, React Router, TanStack Query (server state), Zustand (client state), Axios, React Hook Form + Zod, Tailwind, Lucide.

5. How the four core libraries are organized
Axios (
api.ts
) — single instance with baseURL = VITE_API_URL. Request interceptor attaches Authorization: Bearer <access>. Response interceptor catches 401 → attempts refresh once → on failure clears authStore and redirects to login. Normalizes errors into { message, status } so raw server errors never reach the UI.
TanStack Query — owns all server state: products, stores, categories, orders, profile, and cart. Centralized query-key factory in 
queryKeys.ts
. Defaults: staleTime 5m, gcTime 10m, refetchOnWindowFocus: false (Telegram tab-switching). Mutations for all writes (cart, orders, products) with targeted invalidateQueries. Product/order lists use useInfiniteQuery over ?page=.
Zustand — client-only state: authStore (tokens + user, persisted), uiStore (auth modal, search, selected village/location), appStore (telegramMode, network status). Cart's server data lives in Query; Zustand only holds transient cart UI (e.g. a guest's "pending add to cart" intent before login).
React Router — one central table in routes/, all pages React.lazy()-loaded. Guard wrappers: <PublicRoute>, <ProtectedRoute> (auth), <SellerRoute> (auth + approved store). Layout routes inject the bottom nav. Deep-linking supported for /product/:id, /store/:slug, /orders/:id.
6. Telegram Mini App integration
A 
telegram.ts
 adapter wraps window.Telegram.WebApp and detects environment → sets appStore.telegramMode. Browser falls back to a no-op shim, so the same code runs in both.
On launch it calls ready() / expand(), applies the theme, and wires the Telegram BackButton to router navigation.
An AuthProvider abstracts login strategy: today only phone+password; a telegramLogin() method is defined but stubbed until the backend exposes an initData → JWT endpoint. No throwaway code when that lands.
Layout respects Telegram safe-area insets; bottom nav coexists with Telegram's chrome.
